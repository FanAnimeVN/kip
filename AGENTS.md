# kip — contributor guide for agents and humans

Start with [docs/CONTEXT.md](docs/CONTEXT.md): the problem, research, design decisions, status, and next steps.

## Commands
- `npm ci` — install (dev-only deps: typescript, @types/node)
- `npm test` — build + run `test/kip.test.ts` (node:test)
- `npm run demo` — reproduce the "two directions" story in a temp folder
- `node dist/src/cli.js <command>` — run the local build

## Conventions
- TypeScript, ESM, Node ≥ 18.17, **zero runtime dependencies**.
- Deterministic analysis only (no network/LLM in `src/analyze.ts`).
- Every user-facing string goes through `src/i18n.ts` in both `vi` and `en`.
- Only ever touch kip's own marked block in user files.

## Team context (kip)

Several people work in this repository, each possibly with a different AI coding agent. Keep everyone on the same page:

1. **At the start of a session**, run `node dist/src/cli.js brief` and tell the user, in a few bullets, what teammates changed and every ⚠ warning — before writing code.
2. **Before finishing a task or committing**, run `node dist/src/cli.js check`. If it reports ⚠ divergence, stop and explain it to the user instead of working around it.
3. **Follow the team decisions below.** If a request contradicts one, say so, and suggest recording a new decision with `node dist/src/cli.js decide "<title>"` once the team agrees.

### Team decisions (.kip/decisions.md)

- **Zero runtime dependencies** — npx must be instant and trustworthy (avoid: commander, yargs, chalk, axios)
- **Deterministic core, no LLM required** — precise, free, private; the user's own agent does the explaining
- **Every user-facing string in Vietnamese and English** — students in Vietnam first, global from day one
